# 跨平台同步与本地管理面板设计

## 目标

将 ag-box 从仅 Linux 的跨节点沙盒工具扩展为可在 Linux、macOS 与 Windows 上运行的客户端 CLI 与本地 Web 管理面板。首期支持项目文件及项目关联 agent 会话的加密迁移同步，同时保持现有 Linux 沙盒能力和历史 restic 快照可恢复。

## 范围

首期交付：

- Linux、macOS、Windows 上的可移植 CLI 核心。
- 自托管 S3 兼容对象存储（包括 Cloudflare R2）与 restic 同步。
- Claude Code、Codex、Grok、OpenCode、Pi、oh-my-pi 的会话发现与迁移适配器。
- 仅监听回环地址的本地 Web 管理面板。
- 为未来付费托管保留同步提供方、账号及用量界面边界。

首期不交付：

- Windows/macOS 沙盒、资源限额或进程迁移。
- 浏览器内终端，或从浏览器启动 agent/任意本地命令。
- 托管服务端、多租户账户、支付、订阅、计量和配额执行。

## 架构

代码分为可移植同步核心和 Linux 运行时两层。

- 可移植核心以 Node.js 20+ 实现，负责项目登记、跨平台路径解析、元数据、项目租约、会话收集、快照、恢复与同步。
- Linux 运行时保留 bwrap、systemd-run 和 tmux 的既有沙盒实现；它只由 Linux 命令调用，不能成为可移植核心的依赖。
- `SyncProvider` 为同步后端的抽象。首期唯一实现是 `ResticProvider`，调用本机 restic 和配置的对象存储。未来 `HostedProvider` 通过同一接口使用用户令牌访问托管 API。

项目拥有稳定的逻辑项目 ID，与任何设备上的绝对路径无关。每台设备维护该 ID 到本地工作目录的映射；在新设备恢复时，用户显式选择目标目录。

## 数据与同步语义

同步内容是项目目录及已确认属于该项目的会话文件。认证令牌、agent 全局配置、`.auth-secret` 和用户凭证均不得包含在项目快照中。

项目写操作采用租约：上传、归档或在恢复后接管项目必须先取得项目租约；另一设备持有未过期租约时操作拒绝。用户可以显式强制接管，CLI 与面板均展示可能产生分叉的风险。网络中断、快照失败和恢复失败不得删除或回滚本地项目，且必须保留可诊断的错误信息和最近成功快照。

现有 Linux 元数据必须可读取。升级时为旧盒补充逻辑项目 ID，保留其原路径、已有 restic 标签与历史快照；不得自动移动项目文件。

## 会话适配器

每个 agent 适配器都声明支持的平台、会话根目录候选项、项目匹配规则、可迁移目标及恢复命令模板。适配器覆盖 Claude Code、Codex、Grok、OpenCode、Pi、oh-my-pi。

适配器无法可靠确定会话属于当前项目或不认识版本格式时，必须跳过该会话并报告原因；不得依赖猜测的路径、复制全局会话目录或迁移认证材料。

## CLI 与本地 Web 面板

新增 `ag-box serve`，启动只绑定 `127.0.0.1`/`::1` 的本地 HTTP 服务，并使用每次启动生成的随机访问令牌保护 API。令牌只写入权限受限的运行时文件；浏览器自动打开带令牌的本地 URL。服务不得暴露在局域网或公网。

面板提供：

- 项目登记、本地目录映射、逻辑项目 ID、租约、快照与同步状态。
- 上传、拉取、归档、恢复及其进度、日志和取消操作。
- 已发现会话的 agent 分类和可迁移状态；不返回会话内容与任何凭证。
- 自托管存储配置与诊断。
- 禁用的“托管模式（即将推出）”入口，为日后账户、套餐及用量页面预留位置。
- 本机终端中恢复 agent 的命令提示；不提供 Web 终端且不执行任意命令。

API 只能调用预定义操作。长任务使用任务 ID、状态查询和进度事件；非回环请求、缺少令牌的请求、未知请求字段和任意命令执行请求一律拒绝。

## 依赖与升级策略

restic 是首期同步格式与加密边界。开发开始前必须将当前 Linux 的 restic 从 0.16.4 受控升级到当前稳定版本：先保存版本与仓库状态，执行只读完整性检查和临时目录恢复验证，升级后再次验证同一历史快照可恢复。验证失败则恢复原二进制，不改变仓库。

Windows 和 macOS 客户端也使用官方 restic 二进制；安装程序或首次运行诊断必须检查 Node.js 20+、restic 与选定对象存储配置是否可用。

## 验收与测试

自动化测试必须覆盖：

- Linux 旧元数据与旧快照的兼容与恢复。
- 每种 agent 适配器的路径发现、项目匹配、拒绝未知格式和排除凭证。
- 逻辑项目 ID 与设备本地路径映射。
- 租约竞争、过期、强制接管、同步中断与非空恢复目录。
- `ResticProvider` 命令构造、失败传播和不泄露凭证的日志。
- 本地 API 的回环绑定、令牌验证、输入验证、任务取消与禁止任意命令。
- Linux 既有沙盒测试回归。

Linux、macOS 与 Windows 的端到端冒烟测试必须验证：创建项目、发现至少一个受支持 agent 会话、上传、在另一平台拉取到新目录、恢复会话并检查文件内容。托管模式只测试接口契约，不实现服务端或支付。

## 非目标与后续扩展

未来托管服务实现 `HostedProvider`，负责用户令牌、远端同步 API、对象存储隔离、配额与计量；这不改变 CLI、项目 ID、会话适配器或面板任务 API。支付与多租户身份在托管服务规格中单独设计。
